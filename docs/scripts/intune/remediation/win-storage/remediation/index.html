# Configuration Parameters

# Base Configuration

Contained within region 0C of the remediation script, these exposes a small set of configuration variables, which are explained below.

These configuration variables are declared near the top of the script and are deliberately conservative by default. When deploying via Intune, prefer wrapping the script in a small launcher that sets organisation-specific values instead of editing the script inline.

Parameter Default Description
$oneDriveCleanupThreshold 30 Number of days used by Storage Sense and the probe logic to decide when locally cached OneDrive content is a candidate for cleanup. See Remediation Script Logic for details.
$userProfileRetentionDays 30 Number of days of inactivity after which a local user profile under C:\Users may be considered for removal (whitelisted accounts such as Default, Public remain excluded). See Remediation Script Logic.
$scriptName (string) Base name used for log files and archives (for example Remediate-DiskCleanup-Extended or Win-Storage-Remediate). See Remediation Script Configuration.
$logFile / $tempLogFile / $archiveDirectory / $archiveFile (paths) Paths used for centralised logging and archival. $tempLogFile is a temporary per-run log consolidated into $logFile at the end of the run. $archiveDirectory/$archiveFile are used for per-run archives and fallback archival behaviour. See Logging, troubleshooting and support.
$transcriptStarted (boolean) Internal flag tracking whether Start-Transcript was started successfully so Stop-Transcript can be called safely. See Logging, troubleshooting and support for transcript handling.
$tempLogSizeThresholdMB 5 (or 50 depending on runtime initialisation) If the existing temp log exceeds this size (MB) the script archives it at startup to avoid unbounded temp logs. See Logging, troubleshooting and support.
$tempLogAgeDays 7 If the existing temp log is older than this many days, it is archived at startup. See Logging, troubleshooting and support.
$MaxCleanupDurationMinutes 20 Soft time budget (minutes) used by recursive enumeration/cleanup loops (for example user-temp and global-temp passes). Enumerators check elapsed time and stop when the budget is exceeded. See Remediation Script Logic.
$SKIP_SLOW_IO (switch/env) When set the script reduces retry/backoff and time budgets (useful for unit tests or slow VMs). This is propagated into the environment so helper code can detect fast-path mode.
$cleanupTypeSelection (array) CleanMgr VolumeCache categories configured for cleanmgr.exe registry preparation (the script sets StateFlags0001 so cleanmgr /sagerun:1 will include them). See Defining What to Remove with $cleanupTypeSelection.
$logsToClear (array) List of event log channel names the script will attempt to export and clear using wevtutil. See Defining what Logs to Clear with $logsToClear.

# Defining what cleanup actions to run with per activity preferences

Rather than having to customise the whole script, a set of parameters with true or false values have been defined, so you can choose what cleanup activities are run when the script is executed.

Each associated cleanup activity will only run when the value is set to true, and if false it will provide specific logged output to indicate that it was not run and why.

# Pre-activity preferences (per-activity toggles)

The script exposes a small set of per-activity boolean preferences (variables prefixed with $Pref_) that gate whether a particular cleanup activity will run. These are declared near the top of Win-Storage-Remediate.ps1 and can be used to disable or enable specific sections without editing the region logic.

More information about these functions can be found in Remediation Logic.

Preference variable What it does Default Permitted values
$Pref_RemoveOldUserProfiles Enables removal of old user profiles under C:\Users (Region 2A). The logic honours a whitelist and age threshold ($userProfileRetentionDays). $true $true / $false
$Pref_OneDriveAndBrowserCache Enables per-user OneDrive and browser cache cleanup routines. Uses pruned enumerators and protected-path checks. $true $true / $false
$Pref_DeliveryOptimizationAndWU Enables Delivery Optimization and Windows Update download cache cleanup (SoftwareDistribution\Download, DO cache). $true $true / $false
$Pref_StorageSense Enables Storage Sense configuration and triggering where supported on the host. $true $true / $false
$Pref_DISMComponentStoreCleanup Enables the DISM component store cleanup pass (Invoke-DISM-Safe). This step may be long-running and may require elevation. $true $true / $false
$Pref_ForceDISMWhenPendingOverride File-level preference that forces DISM to run even when a pending reboot is detected. Invoke-DISM-Safe checks this preference in addition to the command-line -ForceDISMWhenPending switch. Use with caution. $false $true / $false
$Pref_EventLogCleanup Enables export and (on success) clearing of selected event logs via the Export-EventLog helper. $true $true / $false
$Pref_UserTempCleanup Enables per-user temp file cleanup (Invoke-UserTempCleanup). $true $true / $false
$Pref_GlobalTempCleanup Enables machine-wide/global TEMP folder cleanup (Invoke-GlobalTempCleanup). $true $true / $false
$Pref_CleanMgrPrep Enables preparation steps for cleanmgr.exe (preparing the list of cleanup types). $true $true / $false
$Pref_RunCleanMgr Enables running cleanmgr.exe to perform CleanMgr-based cleanup (when supported). $true $true / $false
$Pref_RemoveWindowsOld Enables removal of C:\Windows.old. Disabled by default as this is potentially destructive. $false $true / $false

Notes:

  • The preferences are set in the script header; tests or automation can toggle them by editing the script or by supplying wrappers that set these variables in the execution session before invocation.
  • All preferences are boolean; the script uses these variables directly to gate the corresponding region logic. When a preference is $false the region is skipped and a compact summary is recorded in the per-run temp log.
  • Use $Pref_ForceDISMWhenPendingOverride sparingly — forcing DISM while a reboot is pending can interact poorly with servicing actions. Prefer the command-line -ForceDISMWhenPending switch for temporary overrides in automation.

# skipPathPatterns — what they are and why they matter (region 0C)

$skipPathPatterns is an array of regular-expression strings used by Test-IsSkipPath and the pruned enumerator Get-SafeChildItems to avoid touching files and folders that are:

  • OneDrive / Files On-Demand and synchronisation engine files (databases, caches, sidecars, .odl, .odlgz, .aodl). Removing these can lead to user data loss or client corruption.
  • Database files and lock files (.db, .sqlite, .ldb, .db-wal, .db-shm) which are often in use and should not be deleted by a passive cleanup.
  • Core OS and application folders (e.g. Windows, WinSxS, Program Files, ProgramData) and special system files (pagefile.sys, hiberfil.sys, swapfile.sys). These are explicitly protected.
  • Event log and trace files (.evtx, .etl) and Windows Error Reporting items.
  • Crypto and machine key locations which must never be removed.

Key behaviour notes:

  • Patterns are treated as regular expressions where possible (the script attempts regex matching first and falls back to conservative containment checks when a pattern cannot be parsed as regex).
  • The list purposely errs on the side of safety — even if a pattern is broad it is used to prune recursion or skip an item rather than attempt deep deletion. The script treats matches as “do not touch”.
  • Common OneDrive tokens are included, plus explicit file-extension guards for .odl, .odlgz and .aodl which are treated as OneDrive sidecar files.
  • You may tune the $skipPathPatterns for your environment, but do so carefully. Any change that weakens these patterns increases the likelihood of deleting important or in-use files.

# Outputs

  • Logs of actions taken and results saved to $env:TEMP\<scriptName>.log.
  • Disk space recovered, logged as the difference between initial and final free space on the C: drive.

Additional outputs and behavioural notes:

  • Exit codes:
    • 0 = Success (normal completion)
    • 1 = General failure (useful for remote monitoring). Individual step failures are logged but do not always change the exit code unless a fatal condition is detected.
  • Transcripts: the script uses Start-Transcript where available to capture console output. A temporary transcript is consolidated into the main log at the end of the run (or archived if locked).
  • Archival behaviour: the script prefers an atomic Move-Item of the main log into a per-run archive file. If that fails it falls back to append+truncate into a single fallback archive file. If both approaches fail a diagnostic .diag.txt file is written into the archive directory containing the failure details.
  • Log-first behaviour: Write-CustomMessage appends detailed per-run entries (including per-user/profile information) to a temporary per-run log file first. Host output is kept compact and is intended for Intune capture only; inspect the temp log for full details.
  • Retry/backoff and time budgets: removal operations are implemented with per-item retry/backoff and limited by $MaxCleanupDurationMinutes in long enumerations so the script does not get stuck on a single locked/slow subtree.
  • Dry-run semantics: when -DryRun is used the script will log intended actions (for example which files would be removed or archived) but not perform destructive actions like Remove-Item or Move-Item.

# DISM and pending reboot behaviour

  • The DISM component store cleanup step performs a pending reboot check and will skip cleanup if a pending reboot is detected. To override this behaviour use the -ForceDISMWhenPending parameter or set the file-level preference $Pref_ForceDISMWhenPendingOverride = $true when you intentionally want to force DISM to run.

# Recycle Bin estimation

  • Get-RecycleBinSize now returns a stable numeric [int64] value. It attempts a COM-based Shell.Application query first and then falls back to a conservative per-user enumeration of C:\Users\<name>\$Recycle.Bin when COM is unavailable (for example under SYSTEM or constrained hosts). The fallback may under-report and returns 0 on failure.
